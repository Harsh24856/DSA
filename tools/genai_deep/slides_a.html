Deep dive · 0.4 the math of learning

Backpropagation on a computation graph

Every network is a graph of small operations. The forward pass computes values left to right. The backward pass sends one number, ∂L/∂(that node), right to left, and each node multiplies it by its own local derivative. That is the whole algorithm.

Rules you use every day

  • Chain rule: ∂L/∂w = ∂L/∂p · ∂p/∂z · ∂z/∂w.
  • Fan-out adds: if a value feeds two places, its gradient is the sum of both incoming gradients. This is why residual connections pass gradient straight through.
  • Matrix form: for Y = XW, ∂L/∂W = Xᵀ·∂L/∂Y and ∂L/∂X = ∂L/∂Y·Wᵀ. Shapes always match the thing you differentiate.
  • Cost: the backward pass costs about 2× the forward pass, so one training step ≈ 3× a forward pass.

Two results worth deriving once

softmax + cross-entropy: p = softmax(z), L = -log p_y ∂L/∂z = p - onehot(y) sigmoid: σ'(z) = σ(z)(1 - σ(z)) ≤ 0.25
  • The first is why the LLM loss trains so cleanly: the gradient is simply "predicted probabilities minus the truth".
  • The second explains vanishing gradients: 10 sigmoid layers multiply at most 0.25¹⁰ ≈ 10⁻⁶ into the signal.

Check yourself

  1. Why does a residual connection help the gradient?

    For y = x + F(x), ∂y/∂x = I + ∂F/∂x. The identity term carries the gradient back unchanged even when ∂F/∂x is tiny, so deep stacks do not multiply the signal down to zero.

  2. Reverse-mode vs forward-mode autodiff: why do frameworks use reverse mode?

    Reverse mode gives the gradient of one scalar (the loss) with respect to all parameters in one backward pass. Forward mode would need one pass per parameter. With millions of parameters and one loss, reverse mode wins by a huge factor.

  3. What does activation checkpointing trade?

    The backward pass needs the forward activations. Checkpointing stores only some of them and recomputes the rest during backward: less memory, roughly one extra forward pass of compute.

Deep dive · 0.5 generalisation

Why networks generalise: bias, variance, initialisation

Bias and variance

E[(y - ŷ)²] = bias² + variance + noise
  • Bias: error from a model too simple to fit the pattern (underfitting).
  • Variance: error from fitting the quirks of this particular training set (overfitting).
  • Noise: the part no model can remove.
  • Classical view: as models grow, test error falls, then rises (a U shape).

Double descent

Modern networks keep growing past the point where they fit the training set perfectly, and test error falls again. With many parameters, gradient descent tends to find smooth, simple solutions among all the ones that fit (implicit regularisation). This is one reason "bigger plus more data" kept working for LLMs.

Initialisation keeps signals alive

Var(output) = n_in · Var(w) · Var(input) Xavier (tanh): Var(w) = 2 / (n_in + n_out) He (ReLU): Var(w) = 2 / n_in

If each layer multiplies the variance by more than 1, activations explode; by less than 1, they vanish. Picking Var(w) so the factor is 1 keeps every layer in a useful range. ReLU zeros half its inputs, hence the 2 in He init.

Regularisers and what they really do

MethodEffect
Weight decayPulls weights toward 0, prefers smoother functions

Check yourself

  1. Train accuracy 99%, test 70%. Bias or variance problem?

    Variance (overfitting). More data, augmentation, regularisation or a smaller model help. If both were 70%, it would be bias: use a bigger model or better features.

  2. Why use He init instead of Xavier with ReLU?

    ReLU outputs zero for half of its inputs, which halves the variance passed on. He init doubles Var(w) to compensate, so the variance stays constant through depth.

Deep dive · 1.9 inductive bias

Why each architecture fits its data

An architecture is a set of assumptions built into the wiring, called its inductive bias. The right bias means the network learns from less data, because it does not have to discover the structure on its own.

ArchitectureBuilt-in assumptionSymmetry it respectsCost per layer
MLPNone: every input talks to every unitNoneO(n·d)
CNNNearby pixels matter most; patterns repeatTranslation (shift the image, the features shift)O(n·k²·c²)
RNN / LSTMOrder matters; the past is summarised in a stateSame rule at every time stepO(n·d²), sequential
TransformerAny token may matter to any otherPermutation (positions are added explicitly)O(n²·d + n·d²)
GNNInformation flows along edgesRelabelling the nodesO(edges·d)
SSM (Mamba)A compressed running state, like an RNN, but trainable in parallelSame rule at every stepO(n·d), linear

Receptive field

CNN, kernel k, L layers, stride 1: receptive field = 1 + L·(k - 1) Transformer: whole context after 1 layer

A CNN must stack many layers (or downsample) before a pixel can see the whole image. Attention sees everything at once, which is why Vision Transformers need more data: they must learn locality that a CNN gets for free.

The bitter lesson, in practice

  • With little data, strong biases (CNN, GNN) win.
  • With huge data and compute, weaker biases (transformers) catch up and pass them, because they can learn structure the designer did not imagine.
  • Hybrids are common: ConvNeXt (CNN with transformer tricks), Swin (local attention windows), and conv stems in front of ViTs.

Check yourself

  1. Why does a plain transformer need positional information?

    Attention is permutation-equivariant: shuffling the input tokens just shuffles the outputs. Without positions, "dog bites man" and "man bites dog" look the same.

  2. You have 5,000 labelled medical images. ViT from scratch or CNN?

    A CNN (or a pretrained model fine-tuned). The CNN's locality bias makes it far more data-efficient; a ViT from scratch would overfit. A ViT pretrained on a big dataset can also work well when fine-tuned.

Deep dive · 1.10 beyond attention

State space models, linear attention and hybrids

Attention compares every token with every other, so cost grows as n². A whole family of models tries to keep transformer quality with cost that grows as n.

State space models (SSMs)

continuous: h'(t) = A·h(t) + B·x(t), y(t) = C·h(t) discrete: h_t = Ā·h_(t-1) + B̄·x_t, y_t = C·h_t
  • Like an RNN, each step updates a fixed-size state h, so generation is O(1) per token and needs no growing KV cache.
  • Unlike an RNN, the recurrence is linear, so training can run over the whole sequence in parallel (as a convolution or a parallel scan).
  • Mamba makes B, C and the step size depend on the input ("selective"), so the model can choose what to remember and what to forget. Mamba-2 recasts this as a structured form of attention, which runs faster on GPUs.

Linear attention and RNN revivals

  • Linear attention replaces softmax(QKᵀ)V with φ(Q)(φ(K)ᵀV). Computing the right part first makes the cost linear in n.
  • RetNet, RWKV, GLA, DeltaNet: recurrent models with gating that train in parallel.
  • Weakness: a fixed-size state cannot store everything. Exact recall of a detail from far back ("what was the phone number on page 3?") is where pure SSMs fall behind attention.

Hybrids

Many recent long-context models mix a few attention layers (for precise recall) with many SSM or linear layers (for cheap long context). Jamba and several Nemotron and Qwen variants follow this pattern. Treat the exact mix as fast-moving: check each model card.

Check yourself

  1. Why can an SSM generate with constant memory while a transformer cannot?

    The SSM summarises the past in a fixed-size state h. A transformer keeps the keys and values of every past token (the KV cache), which grows with the context length.

  2. What does "selective" add in Mamba?

    The state update depends on the current input, so the model can decide per token to keep or overwrite information. Earlier SSMs used the same fixed dynamics for every token, which made content-based recall hard.

Deep dive · 2.6 the transformer, shape by shape

Follow one batch through a decoder

The residual stream view

  • Each token carries a d-dimensional vector through the whole network. Layers never replace it; they add to it.
  • Attention moves information between tokens (this word reads from that word).
  • The MLP processes information inside one token, and much factual knowledge appears to be stored in MLP weights.
  • Interpretability research reads directions in this stream as features; "induction heads" (copy what followed the last time you saw this token) explain much of in-context learning.

Where the parameters and FLOPs go

per layer ≈ attention 4d² (less with GQA) + MLP 3·d·d_ff (SwiGLU) total ≈ layers × per-layer + vocab·d training ≈ 6 · N · D FLOPs (N params, D tokens) inference ≈ 2 · N FLOPs per generated token
  • The attention scores themselves cost O(T²·d) per layer: small next to the weights at short context, dominant at long context.
  • Chinchilla scaling: compute-optimal training uses about 20 tokens per parameter. Modern models train far beyond that (often 100×+) because a smaller model is cheaper to serve.

Check yourself

  1. Why multiple heads instead of one big attention?

    Each head has its own small Q/K/V projection, so different heads can attend to different things at once (syntax, coreference, position). One head would have to average all of them into a single weighting.

  2. Doubling context from 8k to 16k: what grows, and how?

    Attention score compute and its memory grow about 4× (T²); the KV cache grows 2× (linear in T); the weight-related compute per token stays the same.

Deep dive · 2.7 making attention fast

FlashAttention and the online softmax

On a GPU, moving data is slower than doing math. Naive attention writes the full T×T score matrix to slow GPU memory (HBM), reads it back for softmax, writes it again, then reads it to multiply by V. For long sequences that traffic, not the arithmetic, is the bottleneck.

The trick

  • Split Q, K and V into tiles that fit in fast on-chip memory (SRAM).
  • For each Q tile, stream over K/V tiles and keep a running softmax: the max so far, the denominator so far and the weighted sum so far.
  • The full T×T matrix is never stored. Memory drops from O(T²) to O(T), and the result is exactly the same, not an approximation.
  • Backward recomputes scores from the tiles instead of saving them: more FLOPs, far less memory traffic, faster overall.
new block scores s, old max m, old sum l, old acc a: m' = max(m, max(s)) l' = l·e^(m - m') + Σ e^(s - m') a' = a·e^(m - m') + Σ e^(s - m')·v output = a / l (after the last block)

The memory hierarchy

Later versions (FlashAttention-2 and 3, and similar kernels in vLLM, SGLang and cuDNN) improve how work is split across GPU threads and use newer hardware features such as FP8 and asynchronous copies. In PyTorch you get them through F.scaled_dot_product_attention.

Check yourself

  1. Is FlashAttention an approximation of attention?

    No. It computes exactly the same result as standard attention; only the order of operations and what is kept in memory change. (Sparse and linear attention, by contrast, are approximations.)

  2. Why subtract the running max at all?

    For numerical stability: e^1000 overflows. Subtracting the max keeps every exponent at or below 0. When a later block has a bigger max, the old sums are rescaled by e^(m - m′), which is the core of the online softmax.

Deep dive · 2.8 long context and faster decoding

Stretching context and generating faster

Long context

  • RoPE scaling: position interpolation squeezes new positions into the trained range; NTK-aware scaling and YaRN stretch low frequencies more than high ones, then a short fine-tune on long documents adapts the model.
  • KV cache size is the practical limit. Shrink it with GQA (share K/V across heads), MLA (store a small latent vector per token and expand it when needed), KV quantization (FP8/INT8), and sliding-window layers that only keep recent tokens.
  • Attention sinks: models put a lot of attention on the first few tokens; keeping them in the cache keeps streaming generation stable.
  • Lost in the middle: a long window does not guarantee the model uses it. Facts in the middle are often recalled worse than at the start or end, so test with your own long-context evals ("needle" tests are a minimum, not proof).

Faster decoding

  • Decoding is memory-bound: each new token reads all the weights once. A small extra amount of compute is almost free.
  • Speculative decoding: a cheap drafter proposes k tokens, the big model checks all k in one forward pass, keeps the longest correct prefix and adds one token of its own. The output distribution is unchanged.
  • Drafters: a small model of the same family, extra prediction heads (Medusa, EAGLE) or multi-token prediction heads trained with the model (used by DeepSeek-V3).
  • Reasoning models spend more tokens thinking before answering ("test-time compute"). Quality rises with thinking budget, so latency and cost do too: measure both.
expected tokens per target pass, acceptance rate α, draft length k: (1 - α^(k+1)) / (1 - α) e.g. α = 0.8, k = 4 → 3.4 tokens

Check yourself

  1. Why does speculative decoding not change the output quality?

    The target model verifies every drafted token with a rejection-sampling rule that makes accepted tokens follow exactly the target's own distribution. The drafter only changes speed, never which outputs are possible or how likely they are.

  2. MLA vs GQA: what does each save?

    GQA stores fewer K/V heads and shares them across query heads. MLA stores one compressed latent per token and rebuilds K and V from it, which can shrink the cache further while keeping quality close to full multi-head attention.
