Deep dive · 2.6 attention, one number at a time

Self-attention worked by hand

Attention answers one question for every token: which earlier tokens should I read from, and how much? Each token makes three vectors from its embedding with three learned matrices: a query (what I am looking for), a key (what I contain, for matching) and a value (what I hand over if chosen).

The example (3 tokens, one head of size 2)

tokens: the cat sat Q rows: [2, 0] [0, 4] [2, 2] K rows: [0, 2] [4, 0] [2, 2] V rows: [1, 0] [2, 4] [2, 2]

Scores = Q·Kᵀ / √2, with the causal mask

query ↓ key →thecatsat
the0.00-∞-∞
cat5.660.00-∞
sat2.835.665.66

Softmax per row = attention weights

querythecatsat
the1.00000
cat0.9970.0030
sat0.0290.4860.486

Read it like this

  • "the" can only see itself (the mask), so it copies its own value.
  • "cat"'s query [0, 4] matches "the"'s key [0, 2] strongly, so "cat" reads almost only from "the".
  • "sat" splits its attention between "cat" and itself, so its output [1.97, 2.91] is close to the average of their values.
Why divide by √d_k

If q and k have d_k independent parts with variance 1, their dot product has variance d_k. At d_k = 128 scores would be about 11× larger, softmax would put nearly all weight on one token, and gradients through the other tokens would vanish. Dividing by √d_k brings the variance back to 1.

Check yourself

  1. Why use separate Q and K matrices instead of comparing X with X?

    X·Xᵀ is symmetric: token a would score b exactly as b scores a, and every token would match itself best. Separate W_Q and W_K let "looking for" differ from "offering", so a verb can look for its subject without the subject looking back.

  2. What is the output shape, and how does it get back to d_model?

    Each head outputs (T, d_v). The H heads are concatenated to (T, H·d_v), usually equal to d_model, and multiplied by W_O. The result is added to the residual stream.

  3. Why is attention O(T²)?

    The score matrix has one entry per (query, key) pair: T × T. Doubling the context quadruples the score computation, which is why long context needs FlashAttention, sparse patterns or linear alternatives.

Deep dive · 2.7 heads, masks and cross-attention

Multi-head attention, masks and the three attention types

Masks

  • Causal mask (decoders): position i may attend to positions ≤ i. Implemented by adding -∞ above the diagonal before softmax.
  • Padding mask: in a batch of different lengths, pad tokens get -∞ so nobody attends to them.
  • Sliding window: each token sees only the last W tokens. Several layers stacked still reach far back (receptive field grows W per layer).
  • Document mask: when several documents are packed into one training sequence, block attention across document boundaries.

Check yourself

  1. Does adding heads add parameters?

    Not if the total width stays the same. 8 heads of 64 use the same W_Q, W_K, W_V and W_O sizes as one head of 512; the matrices are just split into slices.

  2. Why can BERT not generate text left to right well?

    It was trained with bidirectional attention to fill in masked words using both sides. Generating needs a causal model that predicts the next token from the left context only, which is exactly what decoder-only training teaches.

Deep dive · 2.8 positions in depth

How a transformer knows word order

Sinusoidal (original transformer)

PE(pos, 2i) = sin(pos / 10000^(2i/d)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d)) x = token_embedding + PE(pos)

Each pair of dimensions is a clock ticking at a different speed: fast clocks tell nearby positions apart, slow clocks tell far ones apart. It is added once at the input.

RoPE (rotary, most modern LLMs)

rotate each pair (x₁, x₂) of q and k by angle pos·θ_i ⟨RoPE(q, m), RoPE(k, n)⟩ depends only on (m - n)
  • Applied to q and k inside every attention layer, not added to the embedding.
  • Rotating both by their own position means the score sees only the distance between tokens: the same pattern works anywhere in the text.
  • Extending context means changing how fast the clocks tick (position interpolation, NTK, YaRN).

ALiBi and none at all

  • ALiBi: no position vectors; add -m·|i - j| to each score, a penalty growing with distance (a different slope m per head).
  • NoPE: causal decoders can infer some position information from the mask alone; some hybrid models drop positions in a few layers.

Check yourself

  1. Why is RoPE applied to q and k but not to v?

    Position should change who attends to whom (the scores), not the content being passed along. Rotating q and k makes the scores depend on relative distance; v stays a pure content vector.

  2. Why do learned absolute positions fail beyond the training length?

    Position 5,000 has no trained embedding if training stopped at 4,096. Sinusoidal and RoPE give every position a defined value, though quality still drops without scaling and some long-context training.

Deep dive · 2.9 training vs generating

One training step and one generation loop, end to end

Training: teacher forcing

text: The cat sat on the mat inputs: The cat sat on the targets: cat sat on the mat (shifted left by one) loss = mean over positions of -log p(target_t | inputs_≤t)
  • All T positions are predicted in parallel in one forward pass. The causal mask stops each position from seeing its own target.
  • Inputs are always the true previous tokens, never the model's own guesses (teacher forcing). That is what makes training fast.
  • Packing: many short documents are joined into one long sequence with separator tokens, so no compute is wasted on padding.
  • For chat fine-tuning, only the assistant's tokens count in the loss (the rest are masked out).

Check yourself

  1. What is "exposure bias"?

    During training the model always sees correct previous tokens; at generation time it sees its own outputs, including mistakes it never saw in training. Errors can compound. Larger models, sampling choices and RL fine-tuning on the model's own outputs reduce the effect.

  2. Why does the prompt's length mostly affect time to first token, while the answer's length affects total time?

    The prompt is processed in one parallel prefill pass, so it adds to the wait before the first token. Every answer token needs its own sequential decode step, so total time grows with output length.
