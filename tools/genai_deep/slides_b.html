Deep dive · 4.7 inside a vector database

Approximate nearest neighbour search

Exact search compares the query with every stored vector: O(N·d) per query. At 100 million vectors that is far too slow, so vector databases use approximate indexes that look at a small fraction of the data and accept missing a few true neighbours. The quality measure is recall@k: what share of the true top-k the index returns.

HNSW: a graph you can walk

  • Every vector is a node linked to about M of its nearest neighbours.
  • Upper layers hold a few random nodes with long links (like express trains); lower layers hold more nodes with short links. Layer 0 holds everything.
  • Search: start at the top, greedily hop to whichever neighbour is closer to the query, drop a layer when stuck, repeat. On layer 0 keep a candidate list of size ef_search.
  • Knobs: M (links per node: memory and recall), ef_construction (build quality), ef_search (query-time recall vs latency).
  • Fast and high recall, but the graph lives in RAM and deletes are awkward.

IVF and product quantization

  • IVF: k-means splits the space into nlist cells. A query searches only its nprobe nearest cells.
  • PQ: cut each vector into m pieces and replace each piece with the id of its nearest of 256 centroids. A 768-float vector (3 KB) becomes m bytes.
  • Distances are computed from a small lookup table per query: fast and tiny, but approximate. Re-score the top candidates with full vectors to get recall back.
  • DiskANN-style indexes keep a graph on SSD with compressed vectors in RAM, for billions of vectors on one machine.

Check yourself

  1. Recall dropped after adding a metadata filter. Why, and what helps?

    With post-filtering, the index returns its top-k first and the filter then removes most of them. Use a database that filters during the graph walk (filtered HNSW), raise k or ef_search when filters are strict, or partition the data by the filter field.

  2. Cosine, dot product or L2?

    Use what the embedding model was trained with. For unit-normalised vectors all three rank results the same way (cosine = dot, and L2² = 2 - 2·cos), so normalise and use dot product, which is the cheapest.

Smaller and cheaper embeddings

  • Matryoshka embeddings: trained so the first 256 (or 128) dimensions already work well. Truncate for a fast first pass, use full length to re-score.
  • Quantization: int8 keeps almost all quality at 4× less memory; binary (1 bit per dimension, Hamming distance) is 32× smaller and very fast, usually followed by float re-scoring.
  • Sparse learned (SPLADE) and BM25 still win on exact terms; keep them for hybrid search.

Better retrieval units

  • Late interaction (ColBERT): keep one vector per token and score with MaxSim. More accurate on hard queries, more storage. ColPali applies the same idea to page images.
  • Contextual retrieval: before embedding a chunk, prepend a short LLM-written sentence saying where it comes from ("This section of the 2025 refund policy covers EU customers"). Cheap with prompt caching and a large recall gain.
  • Parent-child: search small chunks, return their larger parent section to the LLM.

Check yourself

  1. 10M chunks, 1024-dim float32: how much RAM for raw vectors? With binary?

    10M × 1024 × 4 bytes ≈ 41 GB. Binary: 10M × 1024 bits ≈ 1.3 GB, which fits in RAM easily; keep the floats on disk for re-scoring.

  2. When is pgvector the right choice?

    When you already use Postgres and the collection is moderate: you get transactions, joins with your business data and row-level permissions for free, and one fewer system to run. Move to a dedicated store when scale, filtering speed or ops needs outgrow it.

Deep dive · 5.7 LangGraph in depth

State, reducers and control flow

LangGraph models an agent as a state machine. It runs in "super-steps" (from Google's Pregel model): every node scheduled in a step runs, possibly in parallel, their updates are merged into the state, and the edges decide which nodes run next. The state is checkpointed after every super-step.

The pieces

  • State schema: a TypedDict (or Pydantic model). Each key is a "channel".
  • Reducers: how updates to a key are merged. Default is overwrite; Annotated[list, operator.add] appends; add_messages appends and updates messages by id. Without a reducer, two parallel nodes writing the same key is an error.
  • Nodes return only the keys they change.
  • Edges: fixed (add_edge), conditional (add_conditional_edges with a router function), or decided inside a node by returning Command(goto=..., update=...).
  • Send: a router may return a list of Send("node", payload) to fan out one branch per item (map-reduce).

Check yourself

  1. Two parallel nodes both return {"notes": [...]}. What happens without a reducer?

    LangGraph raises an error, because a plain channel can take only one value per super-step. Declare the key with a reducer such as operator.add so the updates are combined.

  2. Conditional edge or Command?

    A conditional edge keeps routing logic separate and visible in the graph definition. Command lets a node update state and choose the next node in one return, which is handy for handoffs between agents. Both compile to the same kind of graph.

Deep dive · 5.8 persistence and humans in the loop

Checkpoints, interrupts and multi-agent graphs

Persistence

  • A checkpointer (InMemorySaver for tests; SQLite or Postgres savers in production) stores a snapshot after every super-step, keyed by thread_id.
  • That gives you conversation memory, crash recovery (resume from the last step), and time travel: list past snapshots with get_state_history, edit one with update_state, and re-run from there.
  • Short-term memory = the thread's state. Long-term memory (facts about a user across threads) goes in a separate Store, searched when needed.

Human in the loop

  • Call interrupt(payload) inside a node. The graph stops, saves state and returns the payload to your app.
  • Resume with invoke(Command(resume=value), cfg). The node restarts from its beginning and interrupt now returns the value, so keep code before it free of side effects.

Multi-agent shapes

  • Supervisor: a central router; easy to reason about.
  • Swarm / handoff: agents pass control directly with Command(goto=...); fewer hops, harder to debug.
  • Each agent can be its own compiled graph used as a node (a subgraph) with its own private state.

Check yourself

  1. Why must code before interrupt() be safe to run twice?

    On resume, LangGraph re-runs the interrupted node from its first line; only the interrupt call returns differently. Anything before it (sending an email, charging a card) would happen again. Put side effects after the interrupt or in a separate node.

  2. Two users chat with the same compiled graph. How is their state kept apart?

    Each conversation uses its own thread_id in the config. The checkpointer stores and loads snapshots per thread_id, so one compiled graph can serve many users.

Deep dive · 5.9 agent protocols

MCP and agent-to-agent protocols

Model Context Protocol (MCP)

  • An open protocol (JSON-RPC) between a host app (Claude, an IDE, your agent), its clients, and servers that expose capabilities.
  • Server primitives: tools (functions the model may call), resources (data the app can read, such as files or rows), prompts (reusable templates the user picks).
  • Client features a server can ask for: sampling (borrow the host's model) and elicitation (ask the user for input).
  • Transports: stdio for local servers; Streamable HTTP for remote ones, with OAuth for auth.
  • Security: treat tool descriptions and results from third-party servers as untrusted input (prompt injection), and scope each server's permissions tightly.

Agent-to-agent (A2A)

  • MCP connects an agent to tools and data. A2A (an open protocol started by Google, now under the Linux Foundation) connects agents to other agents that may run on different frameworks or companies.
  • Each agent publishes an agent card (what it can do, how to reach it). Work is exchanged as tasks with status updates and artifacts, including long-running ones.
  • Rule of thumb: inside one system, a function call or a LangGraph subgraph is simpler. Use a protocol at boundaries you do not own.

Check yourself

  1. Tool vs resource in MCP?

    A tool is an action the model decides to call (search, create ticket). A resource is data the application chooses to load into context (a file, a database row). The model controls tools; the app or user controls resources.

Deep dive · 6.5 post-training theory

From SFT to reinforcement learning with verifiable rewards

The objectives

SFT: L = -Σ log π(y_t | x, y_<t) (loss on answer tokens only) RLHF: max E[r(x, y)] - β · KL(π ‖ π_ref) DPO: L = -log σ( β·[log π(y_w)/π_ref(y_w) - log π(y_l)/π_ref(y_l)] ) GRPO: A_i = (r_i - mean(r)) / std(r) over G samples
  • The KL term keeps the policy near the reference so it does not drift into gibberish that fools the reward model.
  • DPO shows the RLHF optimum can be reached with a classification-style loss on preference pairs: no reward model, no sampling loop.
  • GRPO drops PPO's value network: sample a group of answers per prompt and use each answer's reward relative to the group as its advantage.

Why RL with verifiable rewards (RLVR) took off

  • For math, code and many tool tasks a program can check the answer (unit tests, exact match), so rewards are cheap and hard to fool.
  • Long chains of thought, self-checking and backtracking emerged from this kind of training (DeepSeek-R1 was the well-known open example).
  • Reward hacking still happens: models learn to game weak checkers (special-casing tests). Strong, varied verifiers matter.

Distillation

L = KL( softmax(z_teacher / τ) ‖ softmax(z_student / τ) ) · τ²

A small student copies a big teacher's full probability distribution (or simply its generated reasoning traces). Many small reasoning models are made this way.

Parameter-efficient variants

LoRA and QLoRA (Module 6.2) remain the default. DoRA splits each weight into magnitude and direction and applies LoRA to the direction, often closing part of the gap to full fine-tuning.

Check yourself

  1. What does β control in RLHF and DPO?

    How far the policy may move from the reference. Small β lets it chase the reward (or the preferences) harder, with more risk of degenerate outputs; large β keeps it close to the starting model.

  2. Why does GRPO not need a value network?

    It estimates how good an answer is by comparing it with other answers to the same prompt. The group mean acts as the baseline that PPO's critic would otherwise learn, which saves memory and a whole model.

Deep dive · 7.6 inside an inference engine

How vLLM-style servers get their throughput

Two phases, two bottlenecks

  • Prefill processes the whole prompt in parallel: big matrix multiplies, compute-bound. It sets time to first token (TTFT).
  • Decode makes one token per step and must read every weight and the KV cache each time: memory-bandwidth-bound. It sets time per output token (TPOT).
  • Batching many users in decode is nearly free, because the weights are read once and reused for every sequence in the batch.
decode speed limit, one sequence: tokens/s ≲ memory bandwidth / bytes of weights e.g. 3.35 TB/s ÷ 16 GB (8B in bf16) ≈ 200 tok/s latency ≈ TTFT + output_tokens × TPOT

The techniques

  • Continuous batching: requests join and leave the running batch every step instead of waiting for the slowest one.
  • PagedAttention: the KV cache is stored in fixed-size blocks, like operating-system memory pages, so there is almost no wasted memory and more users fit.
  • Prefix caching (RadixAttention in SGLang): requests sharing a prefix (system prompt, few-shot examples) reuse its KV blocks.
  • Chunked prefill: long prompts are split so they do not freeze everyone else's decoding.
  • Disaggregated serving: prefill and decode run on separate GPU pools, each tuned for its bottleneck, with KV caches shipped between them.
  • Parallelism: tensor parallel (split each matrix across GPUs in one node), pipeline parallel (split layers), expert parallel (spread MoE experts).

Check yourself

  1. TTFT is fine but tokens stream slowly. Which phase, and what helps?

    Decode. It is bandwidth-bound: quantize the weights (fewer bytes to read), use speculative decoding, use a smaller model, or reduce batch contention. Prefill tricks will not help.

  2. Why does prefix caching save so much in RAG and agents?

    The system prompt, tool definitions and long documents repeat across requests. Reusing their KV blocks skips that prefill work entirely, cutting TTFT and cost. Put stable content first so the shared prefix is long.

Deep dive · 8.4 generative image and video theory

From diffusion to flow matching

Diffusion recap

forward: x_t = √ᾱ_t · x₀ + √(1 - ᾱ_t) · ε training: min ‖ ε - ε_θ(x_t, t, text) ‖² sampling: start from noise, denoise step by step
  • Latent diffusion: work in a VAE's compressed latent space (e.g. 8× smaller per side), not pixels. Much cheaper.
  • DDIM and modern solvers sample in 20 to 50 steps instead of 1000.
  • Classifier-free guidance: ε = ε_uncond + w·(ε_cond - ε_uncond). Higher w follows the prompt more closely and lowers diversity.

Flow matching and rectified flow

path: x_t = (1 - t)·x₀ + t·ε (straight line) target: v = ε - x₀ (constant velocity) training: min ‖ v - v_θ(x_t, t, text) ‖² sampling: integrate dx/dt = v_θ from noise back to data
  • Learns a velocity field along straight paths between data and noise. Straighter paths need fewer integration steps.
  • Most recent image and video models (Stable Diffusion 3, FLUX and many video models) use flow matching with a Diffusion Transformer (DiT) backbone instead of a U-Net.
  • Distillation (consistency models, adversarial distillation) cuts sampling to 1 to 4 steps for real-time use.

Native multimodal LLMs

  • Encoder + projector (LLaVA style): a vision encoder turns the image into embeddings, a small adapter maps them into the LLM's token space.
  • Early fusion: images (and audio) become tokens in the same sequence from the start of pretraining, so one transformer reasons across all of them.
  • Speech-to-speech: audio tokens in and out of one model remove the speech-to-text and text-to-speech hops, cutting voice latency.

Check yourself

  1. Why do straight flow paths allow fewer sampling steps?

    Numerical integration is exact for a constant velocity along a straight line: one big step lands in the right place. Curved diffusion paths need many small steps to follow the curve.

  2. Guidance scale 15 gives oversaturated images. Why?

    Guidance extrapolates past the conditional prediction by w times the difference. Large w pushes latents outside the range seen in training, giving harsh colours and artefacts. Typical values are much lower.
