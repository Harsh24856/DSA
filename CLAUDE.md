# DSA Daily

Placement practice tracker, now public: anyone can sign in with Google and gets their own progress. Built by harsh (placements May 2027; plan starts 24 Oct 2026); the schedule constants in `lib/logic.ts` are still his.

## Layout
- Next.js 16 (App Router) + TypeScript + Tailwind v4. Deployed on Vercel (`vercel.json` sets framework `nextjs`).
- `app/`: routes `/` (Today), `/analytics`, `/patterns` + `/patterns/[topic]`, `/problems`, `/genai` + `/genai/[id]`, `/other` + `/other/[subject]` (Roadmap was removed; `/roadmap` redirects to `/other`); `layout.tsx` (fonts, theme script, store, shell); `globals.css` (all design tokens).
- `components/`: `Shell` (sidebar, mobile tab bar, toast), `Settings` (sheet dialog), `ProblemRow`, `charts.tsx` (Recharts + custom heatmap/topic bars), `ui.tsx` (Card, Count, Bar, Seg, Skeleton).
- `lib/`: `problems.ts` (data), `logic.ts` (scheduling + analytics, pure functions), `sync.ts` (Supabase RPC), `store.tsx` (client context: state, actions, sync, theme).
- Patterns section: `lib/patterns/*.ts` (14 topics, 85 patterns: theory, steps, Python template, best/average/worst complexity, traps, visualiser), `lib/patterns/problems.ts` (generated practice lists keyed by LeetCode number), `lib/sim.ts` (simulators that record real algorithm steps as frames), `lib/diagram.ts` (frame types), `components/Visualizer.tsx` (player + 7 renderers), `components/TopicView.tsx`. Pattern problems are separate from the daily plan: ticks live in localStorage `dsa-patterns-v1` and the Supabase `patterns` column via RPC `dsa_patterns_sync` (same sync key), and never touch `lib/problems.ts`, Today or Analytics. The written content is original; the cheatsheets only supplied the pattern list and problem numbers.
- Gen AI section: harsh's Gen AI Engineer Playbook (modules m0 to m12 plus start, interview prep, system design, glossary, resources; m10 to m12 come from `tools/genai_deep/modules_10_12.html`). Deep-dive scripts that need only stdlib, numpy or pydantic (`RUNNABLE` in `GenaiDoc.tsx`) get a "Run in browser" button that runs them in Pyodide (`components/runPython.ts`, loaded on first click). `components/ProgressCard.tsx` ("Share progress" on /genai and /other) draws a PNG card in the current theme. Source is `tools/genai-playbook.html` plus the "Deep dive" theory slides in `tools/genai_deep/slides_*.html` (blocks headed `<!-- @m4 -->` are inserted before that module's Practice slide; `{{code:file.py}}` pulls in a script from `tools/genai_deep`, each of which runs on its own and asserts its own result; `python tools/genai_deep/check.py` runs them all and needs numpy, scikit-learn, pydantic, `langgraph` and `langchain`; blocks headed with a non-module id such as `@design`, `@m9` or `@glossary` are appended at the end of that page); `python3 tools/genai_extract.py` regenerates `lib/genai/content.ts` (one entry per section, classes prefixed `gx-`, styled by the `.gx` block in `globals.css`). `components/GenaiDoc.tsx` renders a section's HTML, draws its mermaid diagrams in the current theme's colors and wires Copy buttons; `GenaiView.tsx` is the page. Interactive labs (`components/labs/`: `kit.tsx` shared frame/slider/ticker, `models.tsx` and `systems.tsx`, 13 labs animated with `motion/react`) are placed by `lib/genai/labs.ts` (section → slide id) and mounted into their slides by `GenaiDoc` with portals. TensorFlow/Keras versions of the 12 PyTorch code blocks live in `tools/genai_tf/*.py` (named after the PyTorch file they mirror; `python tools/genai_tf/check.py` runs and smoke-tests all of them, needs tensorflow + scikit-learn) and are generated into `lib/genai/tensorflow.ts`; `GenaiDoc` adds a PyTorch / TensorFlow switch above each matching block, remembered in `dsa-genai-fw`. "Module done" ticks live in the patterns store under keys `genai:<id>`, so they sync through `progress_patterns_sync` with no schema change.
- Other section (CS core subjects: OS, DBMS, CN, SQL, OOP in Java and C++, Aptitude, plus Programming languages, React and Node.js/Express): typed data in `lib/other/<subject>.ts` (model in `types.ts`, loader in `index.ts`; each page imports only its subject on the server). Text uses a tiny markup rendered by `components/other/Rich.tsx`. Pages: `components/other/OtherHub.tsx`, `OtherView.tsx` (chapters with notes, mermaid diagrams via `components/useMermaid.ts`, code with a Java / C++ switch remembered in `dsa-other-lang`, result tables, interview questions that open on demand, "Done" ticks stored as `other:<subject>:<chapter>` in the patterns store). Ten labs in `components/other/labs-*.tsx` are driven by pure simulators in `lib/other/sim.ts` (page replacement, scheduling, Banker's, sliding window, subnetting, B+ tree, FD closure, dispatch, aptitude generators) and `lib/other/labdata.ts`. `npm run check:other` asserts the simulators against textbook results, runs every SQL answer in SQLite (node:sqlite) and compares it with its result table, compiles and runs every Java and C++ program (needs javac/java and a C++ compiler), runs the Python, JavaScript and TypeScript examples (fixed-port servers go through `lib/other/express-preload.mjs`, which answers one request and closes them) and type-checks every TS/TSX example in `.other-check/`, deleted on success. The source PDFs supplied only the topic list; all text, examples and numbers are original.
- Solve panel (`components/SolvePanel.tsx`): every daily and pattern question has a Solution/Approach button. Hand-written solutions with their own visualisers live in `lib/solutions/` (`arrays.ts`, `structures.ts`, `sql.ts`, keyed by LeetCode slug; currently the first two weeks of the plan, 48 LeetCode + 20 SQL). Everything else shows its closest pattern from `lib/patterns/solveMap.ts` (generated: exact if the question is in a pattern list, else from LeetCode topic tags). New solution batches: add to those files, then `npm run check:solutions` (runs each Python solution against LeetCode examples in `lib/solutions/solutions_test.py`, and every visualiser).
- `public/`: favicon and manifest.
- `trackers/`: the Excel/Google Sheets tracker and the single-file Claude artifact version. `tools/`: generators that produced the original site and xlsx (reference only; `.vercelignore` keeps both off Vercel).

## How it works
- `P` rows in `lib/problems.ts`: `[track L/S/C, title, slug-or-url, level, phase 1-4, topic]`. LeetCode slugs become `https://leetcode.com/problems/<slug>/`.
- Progress lives in localStorage key `dsa-daily-v1`: `{done:{<row index>:{d:"YYYY-MM-DD", h:"s|h|e", r:revisits, n:note, t:ms}}, quota:{L,S,C,wL,wS,wC,v:2}}`. Ticks are keyed by row index, so never reorder or delete rows in problems.ts; only append.
- Today's list per track = lowest-index problems among (done today + undone) up to the daily quota, so extras pull later problems forward and misses roll over. Quotas are per weekday (3 LeetCode + 1 SQL) and per weekend day (3 + 2 + 2 Codeforces), stored with `v: 2`; each track has an add-a-problem button that pulls its next problems forward.
- Hint/Editorial problems resurface in Revisit at +3, +7, +21 days.
- Theme Studio (`components/ThemeStudio.tsx`, `lib/looks.ts`, `components/LookLayer.tsx`): `data-look` on `<html>` picks a look (picture themes from the owner's images in `public/themes` (web-sized copies of `/Users/harsh/DSA/dsa/public/Images`) and credited Unsplash photos, with `data-kind="photo"` glass panels, `data-light` for light ones, pointer parallax and petals/stars/rain effects; drawn themes: paper, blueprint, terminal; absent = Classic palettes). Look tokens live at the end of `app/globals.css`; stored in `dsa-daily-look`.
- Themes: `data-palette` (midnight default, galaxy, ocean, forest, sunset, rose, mono) and `data-theme` (light/dark, absent = follow system) on `<html>`. Stored in `dsa-daily-palette` / `dsa-daily-theme`.
- Sidebar layout: `data-nav` on `<html>` (`rail` icons only, `top` bar across the top, absent = full sidebar), picked in Settings, stored in `dsa-daily-nav`. Desktop only (phones keep the tab bar); Shell styles it with the `nav-rail:` / `nav-top:` Tailwind variants defined in `globals.css`.
- Sign-in and sync: Supabase project `dsa-daily` (ref `dmiiflynxamcooowyhps`, schema in `supabase/schema.sql`). "Continue with Google" via Supabase Auth; `@supabase/ssr` keeps the session in cookies (`lib/supabase/client.ts`, `server.ts`), `proxy.ts` refreshes it on every request; signed-out visitors see `components/SignIn.tsx` as a dialog over the blurred, inert app (old `/login` links redirect to `/` in `next.config.ts`); `app/auth/callback/route.ts` exchanges the OAuth code. Progress lives in table `dsa_progress` (one row per email, RLS read-own) via RPCs `progress_sync` and `progress_patterns_sync` (any signed-in user, own row only, payload size-capped). Local copies are tagged with their owner (`lib/owner.ts`): a different account signing in on the same browser starts clean, and sign-out clears local progress. The client diffs local state against `dsa-daily-base:<email>` and sends only changes, so offline edits sync later. The legacy sync-key row `dsa_state` is kept read-only as a backup; its RPCs are revoked. Supabase Auth URL config: Site URL https://dsa-visualizer-ashy-omega.vercel.app, redirects to /auth/callback on that host and on http://localhost:4000.

## Commands
- `npm run dev`: local dev server on http://localhost:4000
- `npm run build`: production build (must pass before shipping)
- `npm run typecheck`: `tsc --noEmit` (must pass before shipping)
- `npm run check`: rolling-window schedule checks (`lib/logic.check.ts`)
- `npm run check:solutions`: solution examples and visualisers
- `npm run check:other`: Other section simulators, SQL results, Java and C++ programs
- `npm run test:e2e`: Playwright (`e2e/`, `playwright.config.ts`); starts `next dev` on :4100 with `NEXT_PUBLIC_E2E=1`, which makes `lib/store.tsx` act signed in without Supabase. `e2e/navigation.spec.ts` clicks through every route and fails if content is not visible within 500 ms.
- `npm run test:ui`: Playwright UI checks (`e2e/ui.spec.ts`): every page, Settings and Solve at 1280px and 375px in Classic light/dark, Frieren and Starfall; fails on sideways scroll, console errors or text under AA contrast; screenshots land in `test-results/ui/`. Runs `next dev` with `NEXT_PUBLIC_E2E=1` (fake signed-in user, no Supabase); set `E2E_PORT` if 4100 is busy

## Design system
Source of truth: tokens in `app/globals.css`, mapped to Tailwind colors in `@theme inline` (`bg-surface`, `bg-surface-2`, `text-ink`, `text-muted`, `border-line`, `border-line-strong`, `bg-accent`, `text-accent-ink`, `bg-accent-soft`, `text-easy|medium|hard`, `--heat-0..4` for chart intensity).
- Fonts: Geist (UI) and Geist Mono (numbers, `.num`) via `next/font`.
- Icons: `@phosphor-icons/react` only, one family, decorative icons get `aria-hidden`.
- Radius: cards 16px (`.card`, `rounded-card`), panels inside cards 12px (`.tile`, `.inset`, `.callout`, `.code`, `rounded-tile`), controls 10px (`.field`, `.btn`, `.seg`, `rounded-control`), pills and chips full.
- Shared classes (component layer in `globals.css`), use them before writing utilities: headings `.t-title` (28) / `.t-h2` (18, sheets) / `.t-h3` (16, cards and sections) / `.t-eyebrow` (13 muted); buttons `.btn` (40px) + `.btn-sm` (32) / `.btn-lg` (48) / `.btn-icon` / `.btn-ghost` / `.btn-primary` / `.btn-nav`; `.chip` (+ `.chip-accent`, filled when `aria-pressed`/`aria-selected`/`aria-current`); `.seg` via `Seg`; `.tick` checkbox circle; `.pill` + `.lv-*` / `.pill-muted` / `.pill-accent`; `.badge-icon`; `.empty` for empty states; `.scrim` behind sheets. Key numbers use `Stat` from `components/ui.tsx`.
- Motion: `motion/react`, ease `[0.16, 1, 0.3, 1]`, 0.25-0.9s. Every animation has a reason (state change, new content, feedback) and respects `useReducedMotion()` / the reduced-motion CSS block.
- Diagrams (mermaid, drawn by `components/useMermaid.ts` for Gen AI and Other): write them phone-first: `flowchart TB`, at most two nodes side by side, short labels, decision ladders as stacked `subgraph` rows (question --> answer) rather than a chain of diamonds. Tag nodes `:::ok`, `:::bad`, `:::warn` or `:::hot` for token-colored green/red/amber/accent. On narrow screens the hook flips a too-wide `LR` chart (then its subgraphs) to top-to-bottom, shrinks one that is up to 30% too wide, and every diagram gets an Expand button that opens it full screen.
- Charts: colors from tokens only; each chart has a text alternative (`aria-label` summary or visible numbers) and never relies on color alone.

### Cannot ship if
- A component uses a hex/rgb color literal instead of a token (exceptions: palette swatches in `lib/store.tsx`, the dialog scrim in `globals.css`). Check: `grep -rnE "#[0-9a-fA-F]{3,8}\b|rgb\(" app components | grep -v globals.css`
- Any visible string contains an em dash. Check: `grep -rn "—" app components lib`
- An interactive element is a `div` with `onClick`, or an icon-only button lacks `aria-label`.
- `npm run typecheck` or `npm run build` fails.
- A view was not checked in both light and dark mode and at 375px width.
